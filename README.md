# Смена

Сайт учёта работы склада: график дневных и ночных смен, самозапись сотрудников,
выработка по ФБО/ФБС и расчёт затрат на персонал за месяц.

Работает полностью на своём сервере (Docker), без внешних сервисов — чтобы сайт
открывался из России без VPN.

## Кто что видит

| | Комплектовщик | Старший смены | Руководитель склада | Собственник |
|---|---|---|---|---|
| Записаться на смену, свои часы и свои деньги | да | да | да | да |
| Подтверждать записи, ставить людей, часы, «не вышел», закрывать смену | — | да | да | да |
| Вносить факт выработки (ВБ / Озон), отгрузки | — | да | да | да |
| Ставить план на смену, потребность в людях | — | — | да | да |
| Подтверждать регистрации, должности, водители, единицы учёта | — | — | да | да |
| Ставки, выплаты, штрафы, зарплаты, затраты на персонал | — | — | — | да |

Новый человек регистрируется сам (ФИО, дата рождения, телефон, фото) и попадает
в «Новые заявки». Пока его не подтвердили — доступа к графику нет.
Каждый видит только свои деньги; чужие зарплаты и денежные отчёты открыты
только собственникам.

## Как считаются деньги

\
Оплачиваются только выходы со статусом «Подтверждён» в **закрытых** сменах.
Пока смена не закрыта, сумма висит как «ждёт закрытия» и в долг не идёт.
«Не вышел», отклонённые и отменённые в расчёт не попадают.

Ставки хранятся с датой начала действия: подняли цену с 1 октября — сентябрь
пересчитан не будет.

## План, факт и отгрузки

На каждую смену руководитель ставит план: сколько сделать по ВБ и по Озону
в разрезе видов работ (ФБО/ФБС) и единиц (пары, короба, паллеты, заказы).
После смены старший вносит факт в ту же таблицу и оформляет отгрузки:
водитель из справочника, куда (ВБ/Озон и склад), паллеты и короба.
В «Отчётах» — план/факт за месяц с процентом выполнения и сводка отгрузок.

## Запуск на сервере

Нужен VPS с Ubuntu и установленным Docker (Timeweb Cloud, Selectel, Beget,
REG.RU — любой российский провайдер).

### Что заказать

| | Минимум | Рекомендуется |
|---|---|---|
| Процессор | 1 vCPU | 2 vCPU |
| Память | 2 ГБ | 4 ГБ |
| Диск | 20 ГБ NVMe | 40 ГБ NVMe |
| Система | Ubuntu 24.04 LTS | Ubuntu 24.04 LTS |

Меньше 2 ГБ памяти брать не стоит: сборка сайта на сервере съедает около гигабайта
и на 1 ГБ падает. Дополнительно нужен домен (`.ru` дешевле всего) и выделенный IPv4 —
у большинства провайдеров он идёт в тарифе.

### Шаг 1. Домен смотрит на сервер

В панели регистратора домена добавьте А-запись:

```
Тип: A     Имя: @ (или smena)     Значение: <IP вашего сервера>
```

Изменения расходятся по интернету от 15 минут до пары часов. Проверить:
`ping ваш-домен.ру` должен отвечать IP сервера.

### Шаг 2. Docker на сервере

Подключитесь по SSH (`ssh root@IP`) и выполните:

```bash
apt update && apt install -y docker.io docker-compose-v2 rsync
systemctl enable --now docker
```

### Шаг 3. Перенести проект

На своём компьютере из папки проекта:

```bash
sh pack.sh
scp ../smena-deploy.tar.gz root@IP:/root/
```

На сервере:

```bash
mkdir -p /opt/smena && tar -xzf /root/smena-deploy.tar.gz -C /opt/smena && cd /opt/smena
```

### Шаг 4. Настроить и запустить

```bash
cp .env.example .env
nano .env
docker compose up -d --build
```

В `.env` обязательно поменяйте:

```
POSTGRES_PASSWORD=<длинный пароль>
JWT_SECRET=<длинная случайная строка, можно openssl rand -hex 32>
ADMIN_PHONE=<ваш телефон>          # это будет логин руководителя
ADMIN_PASSWORD=<пароль для входа>
SITE_ADDRESS=smena.ваш-домен.ру    # именно домен, без http:// и без слэша
WEB_PORT=80
WEB_TLS_PORT=443
```

Если на сервере `docker compose up` не может скачать образы (Docker Hub с российских
адресов часто недоступен), пропишите зеркало вашего провайдера — например, для Timeweb:

```bash
echo '{"registry-mirrors":["https://dockerhub.timeweb.cloud"]}' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker
```

Caddy сам получит сертификат — сайт откроется по HTTPS. Первый вход —
по `ADMIN_PHONE` и `ADMIN_PASSWORD` из `.env` (учётка руководителя создаётся
один раз при пустой базе; **пароль смените в профиле после первого входа**).

### Обновление сайта

Сделали правки у себя — повторите шаг 3 (`pack.sh` + `scp`), затем на сервере:

```bash
cd /opt/smena && tar -xzf /root/smena-deploy.tar.gz && docker compose up -d --build
```

База и фотографии при этом не трогаются — они лежат в отдельных docker-томах.

### Резервная копия базы

```bash
cd /opt/smena
docker compose exec -T db pg_dump -U smena smena > backup-$(date +%F).sql
```

Раз в сутки автоматически — добавьте в `crontab -e`:

```
0 4 * * * cd /opt/smena && docker compose exec -T db pg_dump -U smena smena > /root/backup-$(date +\%F).sql
```

Фотографии сотрудников лежат в docker-томе `uploads`, сохранить их можно так:

```bash
docker run --rm -v smena_uploads:/data -v /root:/out alpine tar -czf /out/photos.tar.gz -C /data .
```

### Если что-то не поднялось

```bash
docker compose ps          # какие контейнеры живы
docker compose logs api    # ошибки сервера
docker compose logs web    # выпуск сертификата, ошибки Caddy
```

Частая причина отсутствия HTTPS — домен ещё не указывает на сервер: Caddy не может
получить сертификат, пока А-запись не разошлась.

## Разработка на своей машине

```bash
docker compose up -d db          # postgres на localhost:5433
cd server && npm install && npm run dev    # API на :3000
cd web    && npm install && npm run dev    # сайт на :5174
```

Схема БД создаётся автоматически из `db/init/*.sql` при первом старте пустого
тома. Чтобы пересоздать базу с нуля: `docker compose down -v && docker compose up -d db`.

## Из чего состоит

```
db/init/     схема, представления расчёта, стартовые ставки
server/      API на Fastify + PostgreSQL, JWT, загрузка фото
web/         сайт на React + Vite, мобильная вёрстка
```
